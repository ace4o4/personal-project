1. Project Overview & Vision
PropScope is a broker-first real estate intelligence platform for Gurgaon (Gurugram), India. Every project gets a transparent composite score (1-10) based on 7 weighted pillars. The operator is a solo realtor who uses this tool on client calls, shares project links on WhatsApp, and creates YouTube/Instagram content using the scores.
This is NOT a property listing portal. There are no individual unit listings, no buy/sell/rent, no dealer/broker marketplace. It is a scoring and intelligence tool.
1.1 Why Not 99acres
	•	99acres is consumer-first — shows data for browsing, not broker workflow
	•	No scoring, no objectivity, no builder track record analysis
	•	Actively hostile to brokers — hides identity, pushes direct connects
	•	PropScope is the opposite: broker-first interface, buyer-friendly output
1.2 The Moat
	•	Scoring methodology with published weights — transparent and defensible
	•	Ground-truth data from site visits, floor plan analysis, contractor knowledge
	•	Layout & Design scoring (18% weight) requires broker expertise — no AI can replicate without walking sites
	•	Content flywheel: YouTube/Instagram drive traffic, PropScope data fuels content
	•	When competing brokers use your tool, they build your brand
1.3 Revenue Model
	•	Lead capture through quiz and profile creation (Phase 2)
	•	Retargeting pixel on all pages — ad spend only on deep-funnel audiences
	•	Gurgaon: direct lead conversion as operating broker
	•	Other cities: sell leads to verified channel partners
	•	YouTube/Instagram content drives organic traffic
 
2. V1 Scope — Ship in 15 Days
V1 delivers three things only. Nothing else.
2.1 Use Case 1: Quick Filtering on Client Calls
Client says budget, location, category. Broker opens PropScope on phone, applies filters, instantly sees scored project cards sorted by composite score. Talks through top 3 with confidence.
2.2 Use Case 2: Follow-Up & Detail Sharing
After call, share PropScope project page link on WhatsApp. Client sees full score breakdown, area developments, builder profile in a credible, branded format.
2.3 Use Case 3: Social Media Content
Screenshot project cards or score breakdowns for Instagram reels and YouTube shorts. Data backs content, drives traffic to PropScope.
2.4 V1 Deliverables
	•	Project listing page with multi-filter search
	•	Project cards: name, score badge, location, ticket size, category, momentum indicator, USP, image
	•	Project detail page with 7-pillar score breakdown
	•	Builder profile pages
	•	Shareable URLs optimized for WhatsApp (Open Graph tags)
	•	Basic admin for reviewing/editing AI-populated data
	•	Methodology page explaining scoring
	•	Legal disclaimer page + footer disclaimer
	•	~40-60 deeply scored projects across 2 micro-markets at launch
	•	GTM + Meta Pixel on all pages from day one
2.5 V1 Does NOT Include
	•	User login / signup
	•	Buyer profiles or quiz
	•	Personalized scoring
	•	Comparison tool
	•	Rental data
	•	Listings / inventory
Schema for all of the above is created in the database but no UI or API is built.

5. Critical Rules — Read Before Coding
Rule 1: Every table has city_id.
Multi-city is not optional. Noida expansion by EOY 2026.
Rule 2: Sector slugs are unique(city_id, slug), not globally unique.
Sector 63A exists in both Gurgaon and Noida.
Rule 3: Sectors can belong to multiple micro-markets.
Sector 68 is in both SPR and Golf Course Extension. Use project-level micro_market_id as authoritative assignment.
Rule 4: Every project has is_published boolean.
Scraped data enters as is_published = false. Only visible on public site after review. Admin shows unpublished in 'needs review' queue.
Rule 5: Scores are never silently overwritten.
When recalculating, archive current score to score_history with weights snapshot first.
Rule 6: Missing data uses industry average, not flat 5.
For first 30 verified scores per pillar, use manually seeded neutral values from neutral_seed_values table. Switch to rolling average after 30+ verified projects.
Rule 7: Images go to Cloudflare R2, not VPS disk.
Store only URLs in the database. 200 projects × 10 images will fill the SSD.
Rule 8: Follow the scoring rubric exactly.
See Section 7 for complete conversion tables. Do not invent formulas.
Rule 9: No Google Maps API. No paid APIs in V1.
Store lat/lng for future use but do not call external APIs.
Rule 10: Methodology page launches with the site.
It explains the 7 pillars, weights, and bands. It is the trust layer.

PostgreSQL. All tables include city_id for multi-city readiness. Schema is additive — new features add tables, never restructure core.

CREATE TABLE cities (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  slug VARCHAR(100) NOT NULL UNIQUE,
  state VARCHAR(100),
  country VARCHAR(100) DEFAULT 'India',
  is_active BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT NOW()
);

6.2 micro_markets
CREATE TABLE micro_markets (
  id SERIAL PRIMARY KEY,
  city_id INTEGER NOT NULL REFERENCES cities(id),
  name VARCHAR(200) NOT NULL,
  slug VARCHAR(200) NOT NULL,
  description TEXT,
  center_lat DECIMAL(10,7),
  center_lng DECIMAL(10,7),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(city_id, slug)
);

6.3 sectors
CREATE TABLE sectors (
  id SERIAL PRIMARY KEY,
  city_id INTEGER NOT NULL REFERENCES cities(id),
  name VARCHAR(100) NOT NULL,
  slug VARCHAR(100) NOT NULL,
  maturity_level VARCHAR(20),
  UNIQUE(city_id, slug)
);

-- Join table for many-to-many sector-micro_market mapping
CREATE TABLE sector_micro_market (
  sector_id INTEGER REFERENCES sectors(id),
  micro_market_id INTEGER REFERENCES micro_markets(id),
  PRIMARY KEY (sector_id, micro_market_id)
);
NOTE: The project-level micro_market_id is authoritative. This join table is reference only.

7. Scoring Methodology — Complete Rubric
This is the core product. Every formula must be implemented EXACTLY as specified. Do not invent, modify, or improve any calculation.
7.1 Composite Score Formula
composite = (location × 0.25) + (builder × 0.20) + (layout × 0.18) + (density × 0.12) + (amenities × 0.10) + (legal × 0.10) + (value_for_money × 0.05)
Weights read from score_weights table at calculation time — never hardcoded.

12. Data Population Strategy
12.1 AI Does 95%, Operator Verifies 5%
AI agents (Claude Code + scripts) scrape RERA portal, 99acres, builder websites and populate the database. All entries arrive as is_published = false. Operator reviews via admin, adjusts scores, adds USP text and layout assessment, then publishes.

12.3 Launch Data Strategy
Launch with 40-60 deeply scored projects across 2 micro-markets (recommended: Dwarka Expressway + New Gurgaon). Depth is the moat — breadth can be scraped by anyone. Thin data with 'market average pending' tags damages trust.
Expand to 200+ over following 4-6 weeks as operator verifies more projects.
12.4 99acres Note
99acres ToS prohibits scraping and they block aggressively. Treat as research-assisted manual entry, not an automated pipeline you depend on.
